# Datos y evidencias de aprendizaje

## Qué pertenece al repositorio

Currículos, competencias, fuentes, actividades, ejemplos ficticios, criterios, rúbricas y herramientas.

## Qué pertenece al espacio privado

Nombre de una persona, datos de contacto, trabajos identificables, observaciones individualizadas, documentos de experiencia, registros de menores y decisiones de progreso.

El repositorio incluye exclusiones de Git para private y exports. Antes de compartir una copia, se debe comprobar su contenido; una exclusión no elimina archivos ya versionados ni protege por sí sola una carpeta compartida.

## Identificadores y minimización

Para ejemplos se usan alias ficticios. En una futura aplicación, conviene identificar qué dato es necesario para cada función y por cuánto tiempo. El usuario debe poder consultar, corregir y exportar su información.

Un objetivo de aprendizaje suele poder trabajarse sin fecha de nacimiento, domicilio, documento de identidad ni datos clínicos.

## Evidencias

Antes de reunir una evidencia, acordar:
- Qué resultado se quiere observar.
- Qué producto o demostración es suficiente.
- Quién podrá consultarla.
- Dónde se conservará.
- Cómo se revisará o eliminará.
- Qué versión de criterio se aplicó.

El proyecto no solicita datos reales para usar las cinco mallas iniciales.

## Primera infancia y acompañamiento

Las actividades infantiles se realizan con un adulto responsable de preparar materiales y observar la experiencia. La documentación de esta versión propone observaciones generales y ejemplos ficticios. Una implementación con participantes reales requiere definir previamente responsabilidades y condiciones de uso.

## Publicación de trabajos

Un portafolio público puede prepararse como una selección específica y revisada. Se puede utilizar una recreación ficticia que conserve la evidencia técnica o educativa sin mostrar datos ajenos.

## Límites de esta guía

Este documento describe decisiones de diseño y manejo de datos del proyecto. Cualquier aplicación institucional concreta debe verificar las obligaciones y procedimientos que correspondan a su contexto antes de operar con información real.
